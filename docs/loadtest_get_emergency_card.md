# Load Testing `get_emergency_card`

## Overview
This directory contains everything needed to benchmark the **public emergency card** endpoint under concurrent load.

## Seed the Database
1. Run the Supabase migration (if not already applied):
   ```bash
   supabase db reset && supabase db push
   ```
2. Execute the load‑test seed script to generate a realistic dataset:
   ```bash
   psql $SUPABASE_DB_URL -f supabase/seed_loadtest.sql
   ```
   This will insert `NUM_ROWS` (default 1000) fake profiles and dump their `card_public_id`s to `loadtest/card_ids.txt` for the k6 script.

## Run the Load Test locally
```bash
# Set environment variables
export BASE_URL="https://staging.example.com"   # change to your staging URL
export CONCURRENCY=200                         # desired concurrent VUs

k6 run loadtest/k6_get_emergency_card_test.js
```
The script will:
- Ramp up to the target concurrency,
- Keep the load steady for two minutes,
- Record response time percentiles and error rate.

## Results
The output is stored in `loadtest/results.md` (generated automatically by the script). It includes:
- p50, p95 latency values,
- overall error rate,
- a simple summary table.

## Ongoing Execution
- **Manual**: Run the script before each release to verify performance hasn't regressed.
- **CI (optional)**: A GitHub Actions workflow (`loadtest-get-emergency-card.yml`) is provided. It can be triggered manually or on a schedule. By default it is **disabled**; enable it only if you want periodic checks.
